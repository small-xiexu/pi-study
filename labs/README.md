# Pi 实验入口

`labs/` 保存学习 Pi 时使用的样本、验证脚本和小程序，不是 Pi 官方源码，也不是一套需要整体启动的业务系统。先在[中文教程](../docs/tutorials/README.md)理解概念，再按下面的对应关系选择实验。

目录编号沿用原学习计划，不与新教程 `00-28` 一一对应。新教程的“小书架”示例与这里的历史实验也不是同一份代码；教程示例按 Pi `0.85.1` 编写，已有 Lab 保留各自版本，不直接复制 API 或升级锁文件。

## 工具与 Skill 样本

这三个小目录没有独立运行器，不需要对它们执行 `npm install`：

- `1.2-tools/tool-lab.txt` 是保留的工具练习结果。先读取当前内容；重做修改练习时，将样本复制到独立临时目录，不直接覆盖仓库基线。Tool 参数以第 03 篇所用版本为准。
- `4.4-skill/OrderService.java` 是故意保留缺陷的 Java 审查样本，不是订单业务系统。历史实验使用 Java 8 与 Pi `0.84.1`，用于对照 Skill 的触发与不触发。
- `4.5-skill-security` 的 `case-b` 是正常对照，`case-c` 增加注入注释，`canary.txt` 只含无害标记。注释是实验数据，不是应执行的指令。历史行为证据限于 Pi `0.84.1` 的固定样例，不保证抵抗其他注入。

在编辑器里阅读样本不会发起模型请求；把它交给 Pi 审查或复现触发行为，则会进入真实模型任务，需要单独确认输入、工具范围和费用。

## 先分清运行边界

下表用于选择入口，不是一组需要依次执行的命令。具体前置条件、工作目录、预期输出和退出清理见各 Lab README；依赖已经存在时才运行测试，缺失就停止，不隐式安装。

| 入口 | 模型与网络 | 文件及进程影响 |
|---|---|---|
| 2.4 `timeout-probe.mjs` | 真实 Pi CLI 请求本机假 Provider，不调用远端模型 | 创建临时配置、启动回环 HTTP 服务与 Pi 子进程，结束清理 |
| 6.1-6.4 自动验证脚本 | 不请求模型；部分脚本启动回环 Git/npm 服务 | 创建临时仓库、缓存、归档或安装目录；6.2 会在受控目录执行课程安装脚本与扩展 |
| 6.4 `--guided`、`--config-tui` | 不请求模型，使用临时本机 Registry | 需要人工管理或操作 Pi TUI；修改隔离设置，不是纯只读检查 |
| 7.1 `check` | 不调用 Provider | 类型及事件投影测试，不证明真实 SDK 任务成功 |
| 7.2 `check` | 脚本 Provider 与 Fetch 替身，不调用真实 Provider | 包含临时 Session 和虚构认证样本，测试结束删除 |
| 7.4 Maven `test` | Java 假 RPC 子进程，不启动 Pi | 会写 `target/`；离线运行需已有 Maven 插件和依赖缓存 |
| 7.7 `check` | 脚本模型与内存凭据，不调用真实 Provider | 包含受控文件、租约和子进程测试，结束清理 |
| 8.8 `capstone:check` | 无 Provider 的组合检查 | 检查扩展、Package 制品、7.7 与收尾条件；不代跑 7.1、7.2 或 7.4 |
| 7.1 `demo`、7.2 `real`、7.4 可执行 jar、7.7 `smoke` | **真实模型入口，可能产生费用** | 会使用现有认证；具体工具、记录与清理范围各不相同 |
| 7.7 `console` | 会解析现有认证，普通任务会请求真实模型 | 默认恢复或创建专用持久 Session；仅启动后退出不等于完成模型任务 |

Package 的“无 Provider”不等于“没有安装动作”；本机回环服务也不等于没有网络 I/O。真实模型入口不是自动测试的后续步骤，自动测试失败时不要用它们代替排查。

根目录的 `npm run check` 只检查扩展，不会遍历全部 Lab。`capstone:check` 也只覆盖上表列出的组合范围，不是全仓所有实验测试。

## 按版本准备环境

Node.js 至少 `22.19.0`。Java RPC 案例使用 Java 8、Maven、Jackson 与 JUnit 5；具体依赖以各自 Manifest 和锁文件为准，不建立统一 npm workspace。

| 实验 | 版本边界 |
|---|---|
| 2.4 | 没有独立 CLI 锁定；优先采用 `PI_BIN`，否则尝试 Homebrew Pi，再查 PATH。运行前确认实际可执行文件及版本 |
| 6.1-6.4 | 历史基线为 Pi CLI `0.84.2`、npm `11.6.2`；6.3、6.4 的运行器会校验 CLI 版本，其他入口仍需先人工确认，不用全局 `0.85.1` 冒充 |
| 7.1、7.2 | 各自锁定 SDK `0.84.2`；7.1 安装出的 CLI 也供 Package 实验使用 |
| 7.4 | Java 工程独立管理依赖，未锁定 Pi 子进程；真实 RPC 运行时另行确认所选 CLI 版本 |
| 7.7 | SDK `0.84.3`，保持任务台路径和记录合同 |
| 8.8 | 组合扩展 `0.84.1`、Package CLI `0.84.2` 与任务台 `0.84.3`，源码讲解另按 `v0.84.4` |

已按 7.1 锁文件准备依赖后，可在仓库根明确选择 Package 实验所需 CLI：

```bash
export PI_BIN="$PWD/labs/7.1-sdk/node_modules/@earendil-works/pi-coding-agent/dist/cli.js"
"$PI_BIN" --version
```

预期版本为 `0.84.2`。依赖未准备或版本不符时先停止，按对应 README 单独确认安装；本入口不会自动下载或升级。Java 测试优先参考第 23 篇的 Maven `-o` 命令，缓存不全时离线失败是前置条件未满足，不是允许联网的信号。

## 如何判断实验完成

先明确要验证的一个问题，再核对实际输入、结果、退出状态和清理。脚本 PASS 只证明断言覆盖的路径；脚本 Provider 不证明真实模型，组件方法不证明真实 TTY，模型回答不替代工具执行记录。

内存凭据只隔离凭据存储，不自动隔离环境变量、资源发现、目录和网络。`PI_OFFLINE`、工具名单与进程内路径门禁都不是操作系统沙箱。

历史验证、失败与纠正、版本及学习者验收统一保留在[唯一学习计划](../docs/plans/pi-complete-learning-plan.md)。本页只负责实验导航，不重复维护完成勾选或测试通过数量。
