# Java 只读审查清单

只在目标 Java 代码已经定位后读取本清单。根据用户关注点和代码形态选择相关检查项，不要求机械覆盖全部条目。

## 正确性

- 输入边界、空值、空集合、数值范围和状态转换是否完整。
- 条件分支、提前返回和异常路径是否遗漏必要处理。
- 金额表达与计算是否满足业务精度；`BigDecimal` 或整数最小货币单位的比较、舍入和换算是否一致。
- 返回值是否可能掩盖失败、部分完成或未知状态。

## 事务与一致性

- 多个本地写操作是否需要同一事务边界和明确回滚策略。
- 外部调用前后的本地状态变化是否可能留下部分完成状态。
- 重试、超时和重复请求是否可能造成重复扣款、重复写入或重复通知。
- 幂等键的检查与落库是否具备原子性，失败后是否允许安全重试。

## 并发

- 共享可变状态、集合和缓存是否具备线程安全保证。
- “先检查再执行”的多步操作是否可能被并发请求穿透。
- 锁、数据库条件更新或版本控制是否覆盖完整临界区。
- 异步任务与回调是否可能乱序、重复或覆盖较新的状态。

## 错误处理

- 异常是否被吞掉、错误转换是否丢失原因或错误分类。
- 失败路径是否留下已经发生但未补偿的副作用。
- 日志是否包含定位所需上下文，同时避免输出凭据或个人敏感信息。
- 资源是否在成功、失败和取消路径下都能释放。

## 安全

- 外部输入是否进入 SQL、Shell、路径、模板或反序列化入口。
- 认证与授权是否在实际写操作之前完成，并覆盖对象级权限。
- 密钥、Token、支付信息和个人数据是否可能进入日志或错误响应。
- 文件、网络和进程操作是否超出任务明确授权的范围。

## 证据标准

- 仓库文件引用路径与行号，Diff 区分新旧侧位置，匿名片段使用片段行号或方法名并声明来源缺口。
- 把源码直接证明的事实与依赖运行环境的推断分开。
- 缺少调用方、配置、数据库约束或运行日志时，明确列为验证缺口。
- 只给修复方向，不在只读任务中直接修改代码。
